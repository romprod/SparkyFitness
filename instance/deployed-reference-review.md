## Findings and next decisions

No whole-app parity completion is claimed. Outstanding delivered-scope differences above are either explicitly approved adaptations or partial coverage unless a reproducible defect is separately identified. Exact-source synthetic full-page renders now cover stock/preparation, settings/device management, log forms and Bloodwork in active `current` mode. They expose the original layouts and interaction paths, but do not make Sparky pixel-identical or prove the owner’s authenticated saved state.

An isolated fresh-PostgreSQL regression reproduction confirms that deleting a medication with a prepared vial and linked calculated injection fails in the preparation-scope trigger (`P0001`) introduced with preparation records in `0537758be`, leaving the transaction intact. The legacy manual-vial control succeeds and preserves the injection with its medication/vial/preparation references cleared. This delivered-model regression is corrected by forward migration `20261115190000_fix_medication_history_cascades.sql`: genuine parent cleanup clears nullable history references while direct preparation detachment and direct used-stock deletion remain protected. An isolated phase-one snapshot (baseline plus migration/test only) passed fresh migration, reapplication, eight deletion/scope cases, three preparation cases, eight syringe cases and 367 permission cases; the previous server image also passed compatibility. These are source/test results; deployment verification is separate. Tests used synthetic records only, and temporary database/user/tunnel cleanup succeeded. No production deletion was attempted.

A lower-impact API-only invariant gap remains in attaching a preparation to a legacy vial: validation checks the existing usage count/history but can accept a nonzero incoming usage count in the same patch. The normal UI does not submit this combination; balance handling correctly becomes unknown rather than inventing exact stock. This is an own-record consistency edge, not evidence of a new source feature or a cross-owner access issue.

A concrete pre-existing web and native discrepancy requires coordinator review before a fix: a notes/site-only edit rebuilds and sends the timestamp from a minute-precision local control, whereas source `EditDoseForm.tsx` submits a timestamp only if touched and `actions/doses.ts` otherwise keeps the stored instant. Web can strip seconds and change the frozen tracking day; native recombination can additionally shift the stored instant by a whole day. Web baseline code predates these ports; native code is traced to October baseline commit `1468366d72`. Synthetic examples establish the code behavior, not an observed effect on personal records. No native binary has been distributed.

Two further pre-existing web Labs issues were reproduced with synthetic data. At the initial 390-pixel viewport, the header’s More actions button lies entirely beyond the right edge (left approximately 396, right 436), obstructing direct pointer/touch access in that view. Keyboard or horizontal-navigation access was not ruled out. The unchanged header flex layout is in `SparkyFitnessFrontend/src/pages/Labs/Labs.tsx:139–167`; the comparison insertion did not introduce it.

The existing latest-marker/history formatter prioritises `value_numeric` over `value_text`, so a supported dual-field record with a qualifier can lose that qualifier and receive an exact-number In range badge. `SparkyFitnessFrontend/src/pages/Labs/labFormat.ts:56–60` and `Labs.tsx:116–130,228–234` establish the old path; `LabComparison.tsx:35–45` preserves the qualified text in the new matrix. This is a pre-existing loss of qualified-result semantics, not an L02 regression. It does not establish that the example’s In range classification is clinically wrong. No prevalence or impact on personal records was investigated.

The actionable discrepancy count is **five**: one confirmed delivered-model regression, three pre-existing defects (one timestamp issue affecting web/native, two web Labs issues), and one lower-impact API-only invariant edge. Approved adaptations and partial source coverage in the tables are not counted as defects. No new L02 regression was confirmed.

The five audit issues were addressed before the selected flow-completion work. Source-verified candidates after that are preparation/BUD completion, P05 protocol-version history before I06 forecasting, and C01/C02/C06 purchase-cost foundations. These are review options, not implementation authorisation. Do not infer a spill/priming ledger, generic stock adjustment, invoice OCR, numbered syringe ruler or clinical safety rules from the reference.

## Selected flow completion

After the audit-fix releases, the next integration addresses source-visible gaps: a three-step dry/premixed preparation flow and reviewed active-preparation correction; saved-draw editing in four input units with a review/stock-impact step; syringe/pen/pump settings, read-only global availability and route-correct prepared nasal logging; and explicit multi-marker manual panels with full panel history/deletion. The existing Sparky theme, navigation, stock truth and absorption model remain integration requirements.

Preparation correction uses a stable current projection with append-only owner-scoped before/after and per-dose mass audits that survive parent deletion. This replaces the earlier blanket immutable-projection limitation while retaining original input provenance. Source API-only replacement/re-preparation is still deferred; no new re-preparation action or history screen is implied. The new manual panel is explicit membership, not a date-derived grouping of old standalone results. The matrix remains an adaptation of the original optional design capability.

For calibrated history whose original device was removed, source `EditDoseForm.tsx:184–186` and `actions/doses.ts:607` prohibit amount changes, including a fallback to mg. Sparky retains read-only quantity and allows metadata-only correction through its existing compatible API. This does not reinterpret legacy manual-mass rows as calibrated records.

A neutral graphic when no device is saved is an explicit owner-requested adaptation; the original ad-hoc form requires both preparation and device before showing its figure. The placeholder invents no configuration or numeric result. New doses retain their administration-route snapshot; edits preserve it and legacy unknown routes are not backfilled. Additive exact-string readback preserves accepted dose/preparation precision while retaining legacy numeric fields.

The selected flows use the reviewed server/shared snapshot and synthetic full-screen fixtures. The backend gate covers 439 initial integration/permission cases plus a narrowly updated owner-assertion gate (23 affected PostgreSQL cases and 55 route/schema units); this represents 440 unique integration/permission cases with the update.
