## Historical findings from the initial audit

No whole-app parity completion is claimed. Outstanding delivered-scope differences above are either explicitly approved adaptations or partial coverage unless a reproducible defect is separately identified. Exact-source synthetic full-page renders now cover stock/preparation, settings/device management, log forms and Bloodwork in active `current` mode. They expose the original layouts and interaction paths, but do not make Sparky pixel-identical or prove the owner’s authenticated saved state.

The initial isolated fresh-PostgreSQL regression reproduction confirmed that deleting a medication with a prepared vial and linked calculated injection fails in the preparation-scope trigger (`P0001`) introduced with preparation records in `0537758be`, leaving the transaction intact. The legacy manual-vial control succeeds and preserves the injection with its medication/vial/preparation references cleared. This delivered-model regression is corrected by forward migration `20261115190000_fix_medication_history_cascades.sql`: genuine parent cleanup clears nullable history references while direct preparation detachment and direct used-stock deletion remain protected. An isolated phase-one snapshot (baseline plus migration/test only) passed fresh migration, reapplication, eight deletion/scope cases, three preparation cases, eight syringe cases and 367 permission cases; the previous server image also passed compatibility. These are source/test results; deployment verification is separate. Tests used synthetic records only, and temporary database/user/tunnel cleanup succeeded. No production deletion was attempted.

The initial audit found a lower-impact API-only invariant gap in attaching a preparation to a legacy vial: validation checks the existing usage count/history but can accept a nonzero incoming usage count in the same patch. The normal UI does not submit this combination; balance handling correctly becomes unknown rather than inventing exact stock. This is an own-record consistency edge, not evidence of a new source feature or a cross-owner access issue.

The initial audit also found a pre-existing web and native discrepancy: a notes/site-only edit rebuilds and sends the timestamp from a minute-precision local control, whereas source `EditDoseForm.tsx` submits a timestamp only if touched and `actions/doses.ts` otherwise keeps the stored instant. Web can strip seconds and change the frozen tracking day; native recombination can additionally shift the stored instant by a whole day. Web baseline code predates these ports; native code is traced to October baseline commit `1468366d72`. Synthetic examples establish the code behavior, not an observed effect on personal records. No native binary has been distributed.

Two further pre-existing web Labs issues were reproduced with synthetic data. At the initial 390-pixel viewport, the header’s More actions button lies entirely beyond the right edge (left approximately 396, right 436), obstructing direct pointer/touch access in that view. Keyboard or horizontal-navigation access was not ruled out. The unchanged header flex layout is in `SparkyFitnessFrontend/src/pages/Labs/Labs.tsx:139–167`; the comparison insertion did not introduce it.

The existing latest-marker/history formatter prioritises `value_numeric` over `value_text`, so a supported dual-field record with a qualifier can lose that qualifier and receive an exact-number In range badge. `SparkyFitnessFrontend/src/pages/Labs/labFormat.ts:56–60` and `Labs.tsx:116–130,228–234` establish the old path; `LabComparison.tsx:35–45` preserves the qualified text in the new matrix. This is a pre-existing loss of qualified-result semantics, not an L02 regression. It does not establish that the example’s In range classification is clinically wrong. No prevalence or impact on personal records was investigated.

The initial actionable discrepancy count was **five**: one confirmed delivered-model regression, three pre-existing defects (one timestamp issue affecting web/native, two web Labs issues), and one lower-impact API-only invariant edge. Approved adaptations and partial source coverage in the tables are not counted as defects. No new L02 regression was confirmed.

All five audit issues were addressed before the flow-completion release. The historical descriptions above are not outstanding current defects. The selected next tranche is recorded below. Do not infer a spill/priming ledger, generic stock adjustment, invoice OCR, numbered syringe ruler or clinical safety rules from the reference.
